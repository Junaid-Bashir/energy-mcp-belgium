# Recording a short MCP demonstration

Prepare the installed server and your [configured MCP host](clients.md) before recording. This guide is a shot list, not a claim that every model will follow the same path. Record actual calls/results, including clarification or errors. The host owns dialogue; Energy MCP Belgium owns structured retrieval and deterministic calculations.

## Recommended first clip: two meanings of imbalance

Aim for **15–30 seconds**; actual latency depends on the host/model and Elia. Keep the tool-call/provenance panel visible and avoid unrelated account information, credentials, local usernames or authentication screens.

| Approximate time | What to record | Responsibility |
|---|---|---|
| 0–4s | Ask: “What was Belgium's imbalance yesterday?” | User |
| 4–9s | Host asks whether this means physical system imbalance in MW or settlement price in EUR/MWh | Host/model; observed in the validated configuration, not guaranteed |
| 9–12s | Reply: “Imbalance price, between 12:00 and 13:00 UTC yesterday.” | User makes the quantity and a short range explicit |
| 12–22s | Show get_imbalance_prices with explicit start/end arguments | Host invokes the existing MCP tool |
| 22–30s | Show settlement_price_eur_per_mwh, UTC timestamps, source ods134, EUR/MWh and quality status | Structured Elia result |

Show the resolved calendar date on screen whenever using “yesterday.” For a reproducible historical alternative, replace it in both turns with **17 November 2026**, 12:00–13:00 UTC. Do not label those historical prices as current or validated for invoicing if their quality status is provisional. Do not invent a clarification if the host chooses differently; adjust the request or record that outcome honestly.

Suggested caption: **“Physical imbalance: MW. Imbalance price: EUR/MWh. A host can ask which one you mean before fetching.”** Data source: Elia Open Data. This is not an official Elia or MCP-certified product.

## Second clip: deterministic solar energy

1. Ask: “How much solar energy did Belgium produce between 12:00 and 13:00 UTC on 17 November 2026?”
2. Show the host calling calculate_energy with series=solar and explicit bounds.
3. Show energy_mwh, covered_hours, coverage_pct and ods209 provenance. The observed result on 19 November was **2191.975 MWh with 100% coverage**; retain the date and note revisions are possible.
4. Caption: **“The server integrates MW × interval hours into MWh. The language model does not perform the integration.”**

For a terminal-only alternative, enable ENERGY_MCP_LIVE=1 and run:

```sh
python examples/run_public_demo.py --scenario energy --start 2026-11-17T12:00:00Z --end 2026-11-17T13:00:00Z
```

This alternative shows a scripted tool call rather than model-driven selection. For a broader terminal screenshot use all five scenarios as documented in the [demo guide](demo.md), or --scenario quality for load coverage. Keep source units separate from result units.

## Optional later clip: compare generation profiles

Ask for solar and total wind between 12:00 and 16:00 UTC on 17 November 2026. Show get_solar_generation and get_wind_generation calls and the two MW series. If the host also requests energy totals it may call calculate_energy separately for each source. This is a separate clip; do not overload the first demonstration. No new comparison/ranking tool is implied.

## Recording checklist

- Use actual bounded read-only calls, with explicit units, dates and source provenance visible.
- Label synthetic/offline output as synthetic; label the terminal harness as scripted.
- Keep host-dependent selection and provider revision limitations in the accompanying [validation link](validation.md).
- Do not record raw logs or account/session details, and do not commit generated live evidence automatically.
- No video, GIF, external post or marketing distribution is automatically generated by these instructions.
